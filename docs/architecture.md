# Architecture, schema and API
Browser console → bearer-authenticated JSON HTTP API → Store service → SQLite WAL. A background thread runs scheduled draft preparation. Mock actions execute within a serialized SQLite transaction. The mock adapter never accesses the network. Generated artifacts carry product IDs, evidence, confidence and versions.

Tables: `records(kind,id,product_id,data)` stores products, channels, campaigns, actions, leads, schedules, experiments, events and jobs. `(kind,id)` is unique. `audit(seq,at,actor,event,entity,details,previous,hash)` is append-only through the application and SHA-256 chained. `settings` stores emergency pause. The application database owner can still alter database files; this is not an external immutable audit service.

GET /health: unauthenticated minimal liveness. GET /api/state?product_id=1: authenticated state, product-scoped CRM/campaign/event records, metrics and recent audit. POST /api/plan: `{product_id,channel?}` prepares campaign and action. POST /api/actions/:id/approve: `{payload_hash}`. POST /api/actions/:id/revise: `{content?,claims?,evidence?,channel?,destination?}`. POST /api/actions/:id/reject and /execute: `{}`. POST /api/pause: `{paused:true}`. POST /api/tick: scheduled work. POST /api/leads: `{product_id,name,pipeline,stage?}`. POST /api/events: `{product_id,type,source,count?,revenue_cents?,utm_campaign?}`. Source is actual or simulation. POST /api/schedules: `{product_id,due_at,channel?}` with offset-aware ISO timestamp. POST /api/experiments: product-specific experiment metadata.

Successful responses use HTTP 200, authentication failures 401, origin mismatch 403, validation failures 400. Request body limit 256 KiB. No CORS. Bearer token remains in page memory only. Static files have CSP and frame restrictions.
